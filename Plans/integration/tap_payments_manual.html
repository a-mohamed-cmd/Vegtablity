📘 الكتيب المرجعي الفني لربط بوابة Tap Payments (API v2 — الكويت KWD)

تم إعداد هذا المرجع بناءً على فحص التوثيق الرسمي لبوابة Tap Payments (https://developers.tap.company/reference/api-endpoint) لتنفيذه في كلاس TapPaymentProvider ضمن منظومة Vegtablity.

1. إعدادات الاتصال والمصادقة (Authentication & Headers)

  • Base URL الموحد: https://api.tap.company/v2
  • آلية التمييز بين الاختبار (Sandbox) والوضع الفعلي (Live): تستخدم Tap نفس الرابط الأساسي، ويتحدد الوضع تلقائياً حسب المفتاح السري:
    • وضع الاختبار (IsLiveMode = 0): يبدأ المفتاح بـ sk_test_...
    • الوضع الفعلي (IsLiveMode = 1): يبدأ المفتاح بـ sk_live_...
  • الترويسات الإلزامية: 
    Authorization: Bearer {YOUR_TAP_SECRET_KEY}
Content-Type: application/json
Accept: application/json
  • الحساب المحاسبي (يُنشأ فقط بعد حفظ إعدادات البوابة في WPF): حساب حركي باسم Tap Payments تحت الحساب الأب AccountID = 10 (الكود 11).

2. نقاط النهاية المعتمدة (Tap API v2 Endpoints)

العملية Endpoint الوصف
إنشاء عملية تحصيل / رابط دفع مباشر POST /v2/charges إصدار رابط دفع لعملية مفردة أو مجمعة عبر transaction.url مع دعم src_all أو src_kw.knet.
الاستعلام عن حالة عملية تحصيل GET /v2/charges/{charge_id} جلب الحالة الحالية (INITIATED, CAPTURED, DECLINED, TIMEDOUT) ورقم مرجع KNET (reference.payment).
إنشاء فاتورة مستضافة (Tap Invoice) POST /v2/invoices إصدار رابط فاتورة مع بنودها وتاريخ انتهاء الصلاحية وإشعار SMS تلقائي.
الاستعلام عن حالة فاتورة Tap GET /v2/invoices/{invoice_id} فحص حالة الفاتورة (PAID, EXPIRED, CANCELLED).
إعادة إرسال تذكير بالفاتورة POST /v2/invoices/{invoice_id}/remind إعادة إرسال الرابط للعميل غير المسدد.
إلغاء فاتورة معلقة DELETE /v2/invoices/{invoice_id} إلغاء صلاحية رابط قديم.
إرجاع المبلغ للعميل (كلي أو جزئي — Refund) ↩️ POST /v2/refunds إرجاع المبلغ المحصل كلياً أو جزئياً إلى حساب العميل البنكي برقم العملية charge_id مع تحديد السبب reason.
الاستعلام عن حالة عملية الاسترجاع GET /v2/refunds/{refund_id} جلب حالة الاسترجاع (REFUNDED, PENDING, DECLINED).
اختبار الاتصال (Test Connection) POST /v2/charges/list إرسال {"limit": 1} للتحقق من استجابة الخادم وصحة SecretKey.

3. إرجاع المبالغ عبر بوابة Tap (Refunds API — POST /v2/refunds) ↩️

تدعم بوابة Tap استرجاع المبالغ المحصلة (CAPTURED) كلياً أو جزئياً (بدقة 3 خانات عشرية للدينار الكويتي KWD). يتم تفعيل هذه الميزة من إعدادات البوابة عبر الخيار EnableGatewayRefunds الذي يتحكم في إظهار أو إخفاء زر "↩️ إرجاع المبلغ" في صفحة متابعة روابط الدفع (WPF & Flutter):

{
  "charge_id": "chg_TS07A2520261432x9m1004",
  "amount": 12.500,
  "currency": "KWD",
  "description": "استرجاع فاتورة رقم #10452",
  "reason": "requested_by_customer",
  "reference": {
    "merchant": "REF_INV_10452"
  },
  "metadata": {
    "inv_id": "10452",
    "link_id": "88",
    "refunded_by_user": "1"
  },
  "post": {
    "url": "https://your-server-domain/api/integrations/webhook/tap"
  }
}

4. معادلة التحقق من التوقيع الأمني للـ Webhook (hashstring HMAC-SHA256)

عند وصول إشعار الدفع من Tap إلى POST /api/integrations/webhook/tap، يتم التحقق من ترويسة hashstring باستخدام المفتاح السري SecretKey كالتالي:

StringToHash = "x_id" + id
             + "x_amount" + Format(amount, "0.000")   // 3 خانات عشرية للعملة KWD
             + "x_currency" + currency
             + "x_gateway_reference" + reference.gateway
             + "x_payment_reference" + reference.payment
             + "x_status" + status
             + "x_created" + created;

ComputedHash = HMAC_SHA256(StringToHash, SecretKey);

📘 الكتيب المرجعي الفني لربط بوابة MyFatoorah (API v2 — الكويت KWD)

تم إعداد وتحديث هذا المرجع استناداً إلى التوثيق الرسمي لبوابة MyFatoorah (docs.myfatoorah.com) وبالتطابق المعماري الكامل مع بوابة Tap Payments داخل منظومة Vegtablity ERP & POS عبر كلاسات معزولة تماماً في جميع الطبقات (WPF / FastAPI / Flutter) دون استعلامات SQL نصية.

1. عناوين الاتصال الإقليمية والمصادقة (Base URLs & Authentication)

البيئة / الدولة Base URL ملاحظات التشغيل في Vegtablity
الاختبار (Sandbox — جميع الدول) https://apitest.myfatoorah.com الوضع الافتراضي عندما EnvironmentMode = 'Sandbox' (يتطلب Token تجريبي من Sandbox Portal).
الإنتاج — الكويت والبحرين والأردن وعمان https://api.myfatoorah.com الوضع الافتراضي عندما EnvironmentMode = 'Live' لعملاء الكويت (KWD).
الإنتاج — السعودية / الإمارات / قطر / مصر https://api-sa.myfatoorah.com / api-ae / api-qa / api-eg يتم احترام BaseUrl المحفوظ في [Settings].[IntegrationProviders] إذا حدده المستخدم يدوياً.
  • الترويسات الإلزامية (HTTP Headers): 
    Authorization: Bearer {YOUR_MYFATOORAH_API_TOKEN}
Content-Type: application/json
Accept: application/json
  • الدقة العشرية للعملة: جميع المبالغ تُمرر بدقة 3 خانات عشرية (DECIMAL(18, 3)) للعملة الكويتية KWD.

2. نقاط النهاية المعتمدة (MyFatoorah API v2 Endpoints)

جميع نقاط نهاية MyFatoorah API v2 تعمل عبر HTTP POST وتُعيد غلاف الاستجابة القياسي {"IsSuccess": true|false, "Message": "...", "ValidationErrors": [...], "Data": {...}}:

العملية Endpoint الدور في Vegtablity (بالتطابق مع Tap)
1. اختبار الاتصال وجلب وسائل الدفع POST /v2/InitiatePayment التحقق من صحة API Token وتوافق البيئة (Sandbox/Live)، وجلب قائمة وسائل الدفع المتاحة مثل KNET (PaymentMethodId) ورسوم الخدمة.
2. إنشاء فاتورة وإصدار رابط الدفع POST /v2/SendPayment الآلية الأساسية المكافئة لـ POST /v2/charges في Tap لإصدار InvoiceURL وInvoiceId عبر خيار NotificationOption: "LNK" (أو "SMS" / "ALL") مع دعم ExpiryDate وUserDefinedField.
3. تنفيذ دفع موجه لوسيلة محددة (اختياري) POST /v2/ExecutePayment توجيه العميل مباشرةً لوسيلة دفع محددة مثل KNET باستخدام PaymentMethodId المستخرج من InitiatePayment لإرجاع PaymentURL مباشرة دون شاشة اختيار الوسيلة.
4. الاستعلام عن حالة الفاتورة والمعاملات POST /v2/GetPaymentStatus مكافئ GET /v2/charges/{id} في Tap؛ يفحص Data.InvoiceStatus وكذلك مصفوفة Data.InvoiceTransactions (Succss / Failed / InProgress) لتحديد الحالة النهائية بدقة.
5. إرجاع المبلغ للعميل (كلي أو جزئي — Refund) ↩️ POST /v2/MakeRefund مكافئ POST /v2/refunds في Tap؛ يرجع المبلغ المحصل كلياً أو جزئياً باستخدام KeyType: "InvoiceId" مع قراءة Data.RefundId وData.RefundReference ورسائل ValidationErrors.
6. التحقق من حالة الاسترداد ↩️ POST /v2/GetRefundStatus فحص حالة طلب الاسترداد (REFUNDED / PENDING / CANCELED) برقم InvoiceId أو RefundId والتأكد من الرصيد المسترد.
7. استقبال الإشعارات الفورية (Webhook V2) POST /api/integrations/webhooks/myfatoorah التحقق من ترويسة التوقيع MyFatoorah-Signature (HMAC-SHA256 Base64) ومعالجة أحداث PAYMENT_STATUS_CHANGED وREFUND_STATUS_CHANGED.

3. تفاصيل الطلبات والاستجابات الأساسية (Request / Response Contracts)

أ. اختبار الاتصال وجلب الوسائل — POST /v2/InitiatePayment

{
  "InvoiceAmount": 1.000,
  "CurrencyIso": "KWD"
}

يعيد Data.PaymentMethods[] محتوياً على PaymentMethodId (مثلاً 1 لـ KNET، 2 لـ VISA/MASTER)، PaymentMethodCode، ServiceCharge، TotalAmount.

ب. إصدار رابط دفع — POST /v2/SendPayment

{
  "NotificationOption": "LNK",
  "CustomerName": "عميل نقدي",
  "DisplayCurrencyIso": "KWD",
  "MobileCountryCode": "+965",
  "CustomerMobile": "50000000",
  "InvoiceValue": 24.750,
  "Language": "ar",
  "CustomerReference": "INV_10452",
  "UserDefinedField": "INV_10452",
  "ExpiryDate": "2026-11-21T23:59:59",
  "CallBackUrl": "https://your-domain/api/integrations/webhooks/myfatoorah",
  "ErrorUrl": "https://your-domain/api/integrations/webhooks/myfatoorah",
  "CustomerCivilId": ""
}

تُعيد MyFatoorah الحقلين Data.InvoiceId (يُحفظ في ExternalChargeID وExternalInvoiceID) وData.InvoiceURL (يُحفظ في PaymentUrl). وعند استخدام ExecutePayment يُمرر نفس الحقول إضافةً إلى PaymentMethodId ليُرجع Data.PaymentURL.

ج. الاستعلام عن الحالة — POST /v2/GetPaymentStatus

{
  "Key": "3849201",
  "KeyType": "InvoiceId"
}

قواعد ربط الحالة في Vegtablity (بالتطابق مع Tap):

قيمة MyFatoorah (InvoiceStatus / TransactionStatus) حالة النظام الموحدة في InvoicePaymentLinks الأثر التلقائي عبر SQL Trigger
Paid أو معاملة Succss / SUCCESS Paid تفعيل [Sales].[trg_InvoicePaymentLinks_OnStatusPaid] لتوليد قيد التحصيل واحتساب العمولة وترحيل/سداد الفواتير المرتبطة.
Refunded أو إجمالي الاسترداد = مبلغ الفاتورة Refunded تفعيل [Sales].[trg_InvoicePaymentLinks_OnStatusRefunded] لتوليد القيد العكسي الكامل وتحديث PaidAmount.
PartiallyRefunded أو استرداد < مبلغ الفاتورة PartiallyRefunded توليد قيد عكسي بقيمة الجزء المسترد وتحديث الرصيد المتبقي.
Canceled / Cancelled / Expired Expired أو Failed تحديث الحالة دون توليد قيود تحصيل.
Pending مع وجود معاملة أخيرة Failed دون أي معاملة ناجحة Failed تنبيه الكاشير بفشل محاولة الدفع للرابط.

د. إرجاع المبلغ وفحص الاسترداد — POST /v2/MakeRefund & POST /v2/GetRefundStatus ↩️

{
  "KeyType": "InvoiceId",
  "Key": "3849201",
  "RefundChargeOnCustomer": false,
  "ServiceChargeOnCustomer": false,
  "Amount": 24.750,
  "Comment": "استرجاع فاتورة رقم #10452 - طلب عميل"
}

تُعيد الاستجابة الناجحة Data.RefundId وData.RefundReference وData.Amount. وعند وجود خطأ تحقق تُعيد ValidationErrors: [{"Name":"...","Error":"..."}] حيث يتم استخراجها وترجمتها برسالة عربية واضحة للمستخدم.

4. Webhook V2 والتحقق من التوقيع الأمني (MyFatoorah-Signature)

تستقبل نقطة النهاية POST /api/integrations/webhooks/myfatoorah أحداث MyFatoorah V2 (PAYMENT_STATUS_CHANGED / EventType 1، وREFUND_STATUS_CHANGED / EventType 2) مع دعم الحمولات المسطحة (Flat Payloads) أو المتداخلة:

  1. قراءة الترويسة myfatoorah-signature ومقارنتها بتوقيع HMAC-SHA256 (Base64 Binary) باستخدام WebhookSecret عند ضبطه في الإعدادات.
  2. بناء سلسلة التوقيع بترتيب الحقول القياسي (key=value,key2=value2 مع استبدال null بسلسلة فارغة ""):
    • حدث الدفع: Invoice.Id=...,Invoice.Status=...,Transaction.Status=...,Invoice.Reference=... (وفق الحقول المرسلة في الحدث).
    • حدث الاسترداد: Refund.Id=...,Refund.Status=...,Amount.ValueInBaseCurrency=...,ReferencedInvoice.Id=....
  3. تحديث حالة الرابط تلقائياً عبر [Sales].[sp_InvoicePaymentLink_UpdateStatus].

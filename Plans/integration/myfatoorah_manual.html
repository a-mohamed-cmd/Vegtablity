📘 الكتيب المرجعي الفني لربط بوابة MyFatoorah (API v2 — الكويت KWD)

تم إعداد هذا المرجع بناءً على فحص التوثيق الرسمي لبوابة MyFatoorah (https://docs.myfatoorah.com/docs/choose-your-payment-integration) لتنفيذه في كلاس MyFatoorahProvider ضمن منظومة Vegtablity.

1. روابط البيئة والمصادقة (Base URLs & Authentication)

  • بيئة الاختبار (Test / Sandbox — IsLiveMode = 0): https://apitest.myfatoorah.com
  • بيئة الإنتاج الفعلي للكويت (Live Kuwait — IsLiveMode = 1): https://api.myfatoorah.com (أو النطاق الإقليمي https://api-kw.myfatoorah.com)
  • الترويسات الإلزامية (HTTP Headers): 
    Authorization: Bearer {API_Token_Key}
Content-Type: application/json
Accept: application/json
  • الحساب المحاسبي (يُنشأ فقط بعد حفظ إعدادات البوابة في WPF): حساب حركي باسم MyFatoorah تحت الحساب الأب AccountID = 10 (الكود 11).

2. خيارات وطرق التكامل في MyFatoorah API v2

وفق دليل choose-your-payment-integration، يدعم كلاس MyFatoorahProvider طريقتين مرنتين لإصدار روابط الدفع:

  1. طريقة الفاتورة الذكية (Invoice Link — POST /v2/SendPayment):
    • تُنشئ رابط فاتورة شامل (InvoiceURL) ورقم مرجع (InvoiceId) يتيح للعميل اختيار وسيلة الدفع (KNET، Apple Pay، Visa/MasterCard).
    • تدعم خاصية NotificationOption:
      • "LNK": إرجاع الرابط فقط لنظام Vegtablity لطباعته كـ QR Code على الفواتير (58mm / 80mm / WPF) وإرساله عبر WhatsApp.
      • "SMS" أو "ALL": قيام خوادم MyFatoorah بإرسال رسالة SMS مباشرة لهاتف العميل تحتوي على رابط الدفع بالإضافة لإرجاع الرابط للنظام.
  2. طريقة التوجيه المباشر لوسيلة دفع محددة (Direct Gateway Execution — POST /v2/InitiatePayment + POST /v2/ExecutePayment):
    • تتيح تمرير PaymentMethodId (مثلاً 1 لبوابة KNET في الكويت) ليتم تحويل العميل مباشرة إلى شاشة الدفع البنكي KNET دون المرور بصفحة اختيار الوسيلة، مع معرفة عمولة كل وسيلة دفع مسبقاً (ServiceCharge).

3. جدول نقاط النهاية المعتمدة (MyFatoorah API v2 Endpoints)

العملية Endpoint الوصف والحقول الأساسية
فحص الاتصال وجلب وسائل الدفع وعمولاتها POST /v2/InitiatePayment يرسل {"InvoiceAmount": 1.000, "CurrencyIso": "KWD"} ويعيد قائمة PaymentMethods شاملة PaymentMethodId وServiceCharge. يُستخدم أيضاً لزر اختبار الاتصال (Test Connection).
إنشاء رابط دفع فاتورة (منفرد أو مجمع) POST /v2/SendPayment يعيد Data.InvoiceId و Data.InvoiceURL مع دعم ExpiryDate و CustomerReference و UserDefinedField.
تنفيذ دفع مباشر على KNET / وسيلة محددة POST /v2/ExecutePayment يرسل PaymentMethodId و InvoiceValue ويعيد Data.PaymentURL و Data.InvoiceId.
الاستعلام عن حالة الفاتورة / الدفع POST /v2/GetPaymentStatus يرسل {"Key": "...", "KeyType": "InvoiceId" | "PaymentId"} ويعيد Data.InvoiceStatus (Paid, Pending, Canceled) وتفاصيل InvoiceTransactions.
إرجاع المبلغ للعميل (Refund — كلي أو جزئي) ↩️ POST /v2/MakeRefund يرسل KeyType، Key، Amount، Comment، مع خياري RefundChargeOnCustomer و ServiceChargeOnCustomer.
الاستعلام عن حالة الاسترجاع POST /v2/GetRefundStatus يرسل {"Key": "...", "KeyType": "InvoiceId" | "RefundId"} لمتابعة حالة الإرجاع البنكي للعميل.

}

6. التحقق من التوقيع الأمني للـ Webhook v2 (MyFatoorah-Signature)

ترسل MyFatoorah إشعارات Webhook v2 (مثل TransactionsStatusChanged و RefundStatusChanged) إلى POST /api/integrations/webhook/myfatoorah مرفقة بترويسة MyFatoorah-Signature المشفرة بـ HMAC-SHA256 باستخدام مفتاح WebhookSecretKey الخاص بالبوابة.
